# Лабораторная работа №3
## Разработка REST API веб-приложения "Электрические нагрузки автомобиля"

## Цель работы

Закрепление навыков разработки REST API веб-приложений на языке Go, работы с базой данных PostgreSQL, объектным хранилищем MinIO и реализации основных операций с данными.

В ходе выполнения работы был разработан REST API для приложения "Электрические нагрузки автомобиля".

# Полученные знания и навыки

## REST API

В ходе выполнения работы были реализованы HTTP-методы:

- GET — получение данных;
- POST — создание данных и выполнение действий;
- PUT — изменение и публикация данных;
- DELETE — удаление данных.

API принимает и возвращает данные в формате JSON.

Для загрузки изображения и видео используется тип запроса `multipart/form-data`.

---

## Работа с базой данных

Для хранения данных используется PostgreSQL.

Основные таблицы:

- `electric_car_loads` — электрические нагрузки автомобиля;
- `users` — пользователи;
- `likes` — отметки "Нравится".

Для взаимодействия с базой данных используется слой Repository и ORM GORM.

Создание и актуализация структуры таблиц выполняются с помощью `AutoMigrate`.

---

## Работа с файлами

Изображения и видео передаются в REST API как реальные файлы.

Файлы сохраняются в объектном хранилище MinIO.

В базе данных хранятся ключи файлов:

- `image_key`;
- `video_key`.

Имена файлов формируются на стороне backend.

# API приложения

В приложении реализовано 10 различных REST API методов.

## 1. Получение списка опубликованных нагрузок

Метод:

`GET`

URL:

`http://localhost:8080/api/electric-car-loads`

Метод возвращает список опубликованных электрических нагрузок.

Поддерживается необязательная фильтрация по максимальной мощности.

Query-параметр:

`maxPowerW`

Пример:

`http://localhost:8080/api/electric-car-loads?maxPowerW=500`

В ответе для каждой нагрузки возвращается признак:

`is_creator`

Значения:

- `1` — текущий пользователь является создателем нагрузки;
- `0` — текущий пользователь не является создателем нагрузки.

---

## 2. Создание черновика нагрузки

Метод:

`POST`

URL:

`http://localhost:8080/api/electric-car-loads`

Тип тела запроса:

`multipart/form-data`

Передаваемые поля:

- `name` — название нагрузки;
- `image` — файл изображения;
- `video` — видеофайл.

На данном этапе не передаются:

- `description`;
- `category`;
- `power_draw_w`;
- `priority`.

После создания backend автоматически устанавливает статус:

`draft`

Изображение и видео сохраняются в MinIO.

---

## 3. Получение черновика текущего пользователя

Метод:

`GET`

URL:

`http://localhost:8080/api/electric-car-loads/draft`

Метод возвращает черновик текущего пользователя.

Идентификатор черновика в URL не передаётся.

У пользователя может существовать не более одного активного черновика.

---

## 4. Публикация черновика

Метод:

`PUT`

URL:

`http://localhost:8080/api/electric-car-loads/:id`

Пример:

`http://localhost:8080/api/electric-car-loads/12`

Тип тела запроса:

`application/json`

Передаваемые поля:

- `description` — описание нагрузки;
- `category` — категория;
- `power_draw_w` — потребляемая мощность в ваттах;
- `priority` — приоритет нагрузки.

Пример тела запроса:

```json
{
  "description": "Система обогрева заднего стекла автомобиля",
  "category": "ОТОПЛЕНИЕ",
  "power_draw_w": 300,
  "priority": "Средний"
}
```

Публиковать можно только собственный объект со статусом `draft`.

Backend самостоятельно:

- изменяет статус на `published`;
- устанавливает дату публикации `formed_at`.

Системные поля клиентом не передаются.

---

## 5. Получение элемента ленты

Метод:

`GET`

URL:

`http://localhost:8080/api/electric-car-loads/feed`

Без параметров метод возвращает первый опубликованный объект.

Для получения конкретного объекта используется query-параметр:

`id`

Пример:

`http://localhost:8080/api/electric-car-loads/feed?id=12`

Для перехода к следующему опубликованному объекту используются параметры:

`id` и `next=true`

Пример:

`http://localhost:8080/api/electric-car-loads/feed?id=12&next=true`

Все перечисленные варианты относятся к одному REST API методу:

`GET /api/electric-car-loads/feed`

В ответе возвращается поле:

`is_liked`

Значения:

- `0` — текущий пользователь не поставил лайк;
- `1` — текущий пользователь поставил лайк.

Также возвращается поле:

`has_next`

Оно показывает наличие следующего элемента ленты.

---

## 6. Установка или снятие лайка

Метод:

`POST`

URL:

`http://localhost:8080/api/electric-car-loads/:id/like`

Пример:

`http://localhost:8080/api/electric-car-loads/12/like`

Тип тела запроса:

`application/json`

Для установки лайка:

```json
{
  "like": 1
}
```

Для снятия лайка:

```json
{
  "like": 0
}
```

При изменении состояния лайка обновляется поле `like_count`.

---

## 7. Удаление нагрузки

Метод:

`DELETE`

URL:

`http://localhost:8080/api/electric-car-loads/:id`

Пример:

`http://localhost:8080/api/electric-car-loads/12`

Используется логическое удаление.

Запись физически не удаляется из таблицы.

Backend изменяет статус нагрузки на:

`deleted`

Удалять можно только собственную нагрузку.

---

## 8. Регистрация пользователя

Метод:

`POST`

URL:

`http://localhost:8080/api/users/register`

Тип тела запроса:

`application/json`

Пример:

```json
{
  "name": "test_user",
  "password": "123456"
}
```

Метод создаёт нового пользователя.

---

URL:

`http://localhost:8080/api/users/auth`

Тип тела запроса:

Пример:

# Структура базы данных

## Таблица `electric_car_loads`

Таблица содержит данные об электрических нагрузках автомобиля.

Основные поля:

- `id` — первичный ключ;
- `name` — название нагрузки;
- `description` — описание;
- `status` — статус нагрузки;
- `image_key` — ключ изображения в MinIO;
- `video_key` — ключ видео в MinIO;
- `category` — категория;
- `power_draw_w` — потребляемая мощность;
- `priority` — приоритет;
- `like_count` — количество лайков;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения;
- `formed_at` — дата публикации;
- `creator_id` — идентификатор пользователя-создателя.

Возможные значения `status`:

- `draft`;
- `published`;
- `deleted`.

На этапе создания черновика поля:

- `description`;
- `category`;
- `power_draw_w`;
- `priority`

могут быть не заполнены и заполняются при публикации.

---

## Таблица `users`

Таблица содержит данные пользователей.

Поля:

- `id` — первичный ключ;
- `name` — имя пользователя;
- `password` — пароль;
- `created_at` — дата создания пользователя.

---

## Таблица `likes`

Таблица содержит информацию о лайках пользователей.

Поля:

- `id` — первичный ключ;
- `user_id` — идентификатор пользователя;
- `electric_car_load_id` — идентификатор электрической нагрузки.

По наличию записи в таблице `likes` определяется значение поля `is_liked`.

Если запись для пары `user_id` и `electric_car_load_id` существует:

`is_liked = 1`

Если записи нет:

`is_liked = 0`

---

# Связи между таблицами

Связь:

`users.id -> electric_car_loads.creator_id`

означает, что один пользователь может создать несколько электрических нагрузок.

Связь:

`users.id -> likes.user_id`

означает, что один пользователь может иметь несколько записей о лайках.

Связь:

`electric_car_loads.id -> likes.electric_car_load_id`

означает, что одна электрическая нагрузка может иметь несколько лайков.

Таблица `likes` является связующей таблицей между пользователями и электрическими нагрузками.

# Работа с текущим пользователем

Для лабораторной работы используется упрощённый механизм определения текущего пользователя.

Идентификатор пользователя задаётся константой:

`fixedUserID`

Для однократной инициализации используется:

`sync.Once`

Функции:

- `CurrentUser()`;
- `CurrentUserID()`

используются API-методами для определения текущего пользователя.

# Проверка работы

Работа REST API проверяется с помощью Postman.

В коллекции используется 10 различных REST API методов:

1. GET списка нагрузок;
2. POST создания черновика;
3. GET черновика;
4. PUT публикации;
5. GET ленты;
6. POST установки или снятия лайка;
7. DELETE нагрузки;
8. POST регистрации пользователя;
9. POST авторизации;
10. POST выхода пользователя.

Дополнительно проверяются разные варианты вызова метода ленты:

- без параметров;
- с параметром `id`;
- с параметрами `id` и `next=true`.

Это варианты одного метода:

`GET /api/electric-car-loads/feed`

Изменения в базе данных проверяются с помощью SQL-запросов `SELECT`.
