# Лабораторная работа №3
## Разработка REST API веб-приложения "Электрические нагрузки автомобиля"

## Цель работы

Закрепление навыков разработки REST API веб-приложений на языке Go, работы с базой данных PostgreSQL и реализации основных операций с данными.

В ходе выполнения работы был разработан REST API для приложения электрических нагрузок автомобиля.

---

# Полученные знания и навыки

## REST API

В ходе выполнения работы были реализованы HTTP-методы:

- GET — получение данных;
- POST — создание данных и выполнение действий;
- PUT — изменение и публикация данных;
- DELETE — удаление данных.

API возвращает данные в формате JSON.

---

## Работа с базой данных

Для хранения данных используется PostgreSQL.

Основные таблицы:

- `electric_car_loads` — электрические нагрузки;
- `users` — пользователи;
- `likes` — отметки «Нравится».

Для работы с базой данных используется Repository.

---

## Модели и сериализаторы

Основные модели приложения:

- `ElectricCarLoad` — электрическая нагрузка;
- `User` — пользователь;
- `Like` — отметка «Нравится».

Для формирования запросов и ответов API используются сериализаторы.

---

# API приложения

Основные методы:

- `GET /api/electric-car-loads` — получение списка нагрузок с фильтрацией;
- `POST /api/electric-car-loads` — создание черновика с изображением и видео;
- `GET /api/electric-car-loads/draft` — получение черновика;
- `PUT /api/electric-car-loads/:id` — публикация нагрузки;
- `GET /api/electric-car-loads/feed` — получение ленты;
- `GET /api/electric-car-loads/feed?id=:id&next=true` — получение следующего элемента ленты;
- `POST /api/electric-car-loads/:id/like` — установка или снятие лайка;
- `DELETE /api/electric-car-loads/:id` — удаление нагрузки;
- `POST /api/users/register` — регистрация пользователя;
- `POST /api/users/auth` — авторизация;
- `POST /api/users/logout` — выход из системы.

---

# Работа с пользователем

Для лабораторной работы используется упрощённый механизм определения текущего пользователя.

Идентификатор пользователя задаётся константой `fixedUserID`.

Для однократной инициализации используется `sync.Once`.

Функции `CurrentUser()` и `CurrentUserID()` используются API-методами для определения текущего пользователя.

---

# Проверка работы

Работа REST API проверяется через Postman / Insomnia.

Проверяются:

- получение списка с фильтрацией;
- добавление услуги с изображением и видео;
- получение черновика;
- публикация услуги;
- получение ленты;
- переход к следующему элементу;
- установка лайка;
- удаление услуги;
- регистрация пользователя.

Изменения в базе данных проверяются с помощью SQL-запросов `SELECT`.
